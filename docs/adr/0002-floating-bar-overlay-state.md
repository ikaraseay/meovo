# 悬浮栏的浮层状态归 store 管，层级走 token 刻度

设置弹窗能盖住导航栏；站内跳一页，栏体和设置按钮就弹回默认位置；刷新浏览器，同样不记得。
三个症状看起来是三件事，其实是同一件：**浮层的几何状态没有主人**。

**为什么跳页会复位？** 栏体、设置按钮、设置弹窗、抽屉的位置都活在 `FloatingBar.astro`
脚本的模块级变量里（`menuX` / `fabRight` / `popupX` / `drawerHeight`）。变量随页面卸载而消失，
而站点是静态输出、没开 view transitions —— 站内任何一次跳转都是整页加载，脚本重新执行，
变量回到初值。所以「跳转复位」和「刷新复位」是同一个根因的两种表现。

**为什么设置弹窗能盖住导航栏？** 四个面各自写着裸 `z-index`（9999 / 10000 / 10000 / 10001），
彼此没有约定，「谁盖住谁」由谁碰巧写的数大决定。设置弹窗数值最大，于是它盖住栏体和二级面板；
两个面板也可以同时开着，谁也不让谁。

**怎么改？**

1. 浮层的几何状态归一个 store 管 —— `frontend/lib/floating-bar-state.ts`。接口只有两个函数：
   读整份状态、按块写。键名、序列化、坏值处理都在实现里，调用方不用知道。
   写只覆盖自己那一块 —— 存栏体不会把设置按钮的位置抹掉。
2. 层级刻度集中在 `tokens.css` 的 `--ui-z-*`，组件里不写裸 `z-index`。
   层序由语义决定：栏体 → 二级面板 → 设置按钮 → 设置弹窗。
3. 同一时刻只有一个覆盖层 —— 设置弹窗与二级菜单面板互斥，打开一个必然关掉另一个。
4. 还原只夹取，不重置 —— 视口变了就按新尺寸夹回可见范围，绝不改成默认值。
   **栏体的位置记成视口比例**（`menu: {fx, fy}`）而不是像素：分辨率变了栏体按比例跟着走，
   用户摆在视口里的相对位置不丢；旧格式的绝对像素按当前视口换算成比例，升级那刻位置不跳。
   用户没摆过栏体时那一块不落盘 —— 默认的「顶部居中」每次重算，分辨率一变仍然居中。
5. 自动落点要避让 —— 设置弹窗自动落在视口中间时避开栏体；用户自己拖过的位置不动。

**代价（明确接受）**：store 只有一个后端（localStorage），seam 现在只有一个实现，
换成 sessionStorage 或跟服务端同步时再抽；**设置弹窗的位置还是绝对像素** ——
它是一次性的浮层，夹取修正就够了，不跟栏体一起改成比例；
抽屉的展开状态也一起存了 ——
抽屉高度是用户拖出来的，同一个毛病，顺手一起治。

**Consequences**：`FloatingBar.astro` 里不再有散装的浮层状态，只有 store 和「这一帧画在哪」。
以后加新浮层，几何状态加进 store、层级加进 `--ui-z-*`、互斥规则写在打开函数的第一行。
